Static Analysis

      

      

        Runs CodeQL queries (path existence + taint flow) directly on your
        source. UI-only constraints; anything involving call(api)/status(api)
        or future-work types skips automatically.

Dynamic Analysis

      

      

        Drives your running app under Playwright, generates traces by clicking the
        constraint's action elements (plus a few random extras for variation), and
        compares the observed probability of the event against the constraint.
        


        Default URL is the bundled demo app
        (/run/) served by this same Flask process. Replace it with
        your own app's URL if you want to verify against a real running app.
      

      

        
        
        
      

      

    


  


  


  
  


    
    

      
Inject IDs into source

      

        Add stable IDs (cv_0001, cv_0002, …) to every UI
        element in your source so CodeQL can locate them from constraints. This
        rewrites your HTML / JS files in place. If the target isn't a git repo,
        a .bak copy is written alongside every modified file.
      


      

        
        
      


      

      

    


    
    

      
Element list

      

        Walk the same source path and list every DOM id (with its derived label).
        Used by the Parser tab for autocomplete chips and by Visitor 2 to flag
        unknown identifiers.
      


      

        
        
      


      

    


    
    

      
Build CodeQL database

      

        Indexes the same source into a CodeQL database so static analysis
        can run queries against it. Required before any static check; safe
        to re-run after you change the source. Building also switches
        /run/ to serve this source so preview and the DB stay
        in sync.
